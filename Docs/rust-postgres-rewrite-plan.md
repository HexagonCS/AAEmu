**AAEmu Rust + PostgreSQL Rewrite Plan**

- Doc owner: Platform/Infra
- Last updated: 2025-08-08
- Sources referenced: README.md, Docs/components.md, Docs/compact-sqlite.md, Docs/mysql-aaemu_game.md, AAEmu.Login/README.md, AAEmu.Game/README.md, SQL/*.sql

**Goals**
- Replace `.NET` services with Rust while preserving behavior and network protocol compatibility.
- Replace MySQL with PostgreSQL for runtime state; keep `compact.sqlite3` for static reference data.
- Minimize downtime and enable incremental migration with clear rollback points.
- Improve reliability, performance, and observability without changing external client behavior.

**Non‑Goals**
- Changing client protocol or gameplay semantics.
- Replacing the `compact.sqlite3` data source.
- Large schema redesign beyond necessary MySQL→PostgreSQL adaptations (may follow later).

**Current State Summary**
- Services: `AAEmu.Login` and `AAEmu.Game` in .NET; shared code in `AAEmu.Commons`.
- Runtime DBs: MySQL 8 databases `aaemu_login`, `aaemu_game` (see SQL/aaemu_*.sql and Docs/mysql-aaemu_game.md).
- Static data: `AAEmu.Game/Data/compact.sqlite3` (docs in Docs/compact-sqlite.md); many text fields are Korean; prefer ID-based lookups.
- Startup flow: Game server loads design data from SQLite, persists state in MySQL, exposes game/stream ports.

**Target Stack**
- Language: Rust 1.79+ (MSRV pinned in `rust-toolchain.toml`).
- Async runtime: Tokio.
- HTTP/WS (if needed): Axum.
- TCP game protocol: custom framed codec with `tokio-util`/`bytes`.
- Serialization: Serde + bespoke protocol serializers.
- DB (PostgreSQL): `sqlx` (compile‑time checked, offline mode) or `SeaORM` (if richer ORM desired). Start with `sqlx` for control/perf.
- DB (SQLite reference): `rusqlite` with read‑only, shared cache; optional `sqlx` feature for SQLite if unifying.
- Migrations: `sqlx migrate` (or `refinery`) with raw SQL.
- Config: `figment` or `config` crate with env overrides; support `.env` for dev, secrets via env in prod.
- Observability: `tracing` + `tracing-subscriber` (JSON); metrics via `prometheus`.
- Container: multi‑stage `Dockerfile` using `rust:slim`; Postgres 16; `docker compose`.

**Rust Workspace Layout**
- `crates/aaemu-protocol`: packet structs, codecs, feature‑gated compatibility tests against recorded traffic.
- `crates/aaemu-core`: domain types, error handling, time utils, IDs.
- `crates/aaemu-net`: TCP listeners, session mgmt, encryption/compression as needed.
- `crates/aaemu-data-sqlite`: read‑only access to `compact.sqlite3` (items, skills, effects, localization helpers).
- `crates/aaemu-pg`: PostgreSQL repository layer (auth, accounts, characters, inventories, mail, housing, etc.).
- `services/login`: Rust login service binary.
- `services/game`: Rust game service binary.
- `tools/migrate`: data migration CLI (MySQL→PostgreSQL) and verification checks.

**PostgreSQL Design Decisions**
- Schemas: keep `aaemu_login`, `aaemu_game` as separate PG schemas or databases (prefer separate DBs in one server).
- Types mapping:
  - `TINYINT(1)`→`boolean`; other `TINYINT`→`smallint`.
  - `INT`→`integer`; `BIGINT`→`bigint`.
  - `AUTO_INCREMENT`→`generated always as identity` (or `generated by default` when needed for bulk loads).
  - `DATETIME`/`TIMESTAMP`→`timestamptz` (UTC); store UTC only.
  - `BLOB`→`bytea`; `TEXT`→`text`; `JSON`→`jsonb`.
  - `ENUM`→PG `enum` or `text`+`check`; start with `text`+`check` for agility.
- Collation/case: PG uses ICU collations differently; normalize strings and indexes explicitly; avoid case‑sensitive traps.
- Referential integrity: preserve FKs/cascades; drop MySQL `ON UPDATE CASCADE` where unnecessary.
- Indexing: review composite indexes; add partial indexes for common predicates; use `btree` by default.
- Concurrency: use connection pools (`sqlx` + `deadpool` if needed); keep transactions short; prefer `SELECT … FOR UPDATE SKIP LOCKED` for queues.

**SQLite Strategy (Keep As‑Is)**
- File path remains `./Data/compact.sqlite3` relative to binary (see Docs/compact-sqlite.md).
- Access via `rusqlite` in read‑only mode: `OpenFlags::SQLITE_OPEN_READ_ONLY | SQLITE_OPEN_SHARED_CACHE | SQLITE_OPEN_NO_MUTEX`.
- Provide typed query helpers by table domain: items, skills, doodads, quests, localization.
- Cache warm‑up: selective prefetch of hot tables/indices at startup with bounded memory; avoid full in‑RAM duplication.

**Incremental Migration Plan (Strangler Fig)**
Phase 0 — Inventory & Verification
- Freeze protocol spec from `.NET` code (`AAEmu.Commons/Network`) and capture packet traces and golden behaviors.
- Export current MySQL schemas and row counts; identify MySQL‑specific constructs.
- Define acceptance tests mirroring `AAEmu.UnitTests` behaviors that touch DB/network.

Phase 1 — Database Preparation (PG sidecar)
- Provision PostgreSQL; create empty `aaemu_login`, `aaemu_game` with adapted DDL.
- Build `tools/migrate` CLI: schema diff tool + loader (MySQL→PG) with idempotent runs.
- Run full migration dry‑run; validate counts, checksums, and selected invariants.

Phase 2 — Rust Login Service
- Implement `services/login` in Rust with protocol parity; back it by PG only.
- Introduce compatibility mode: .NET Game can authenticate via Rust Login (config: host switch to `login-rs`).
- Run canary; soak test; decommission .NET Login.

Phase 3 — Rust Game Service (vertical slices)
- Implement minimal session loop, movement, chat, and simple queries using PG + SQLite.
- Replace subsystems incrementally: accounts/characters → inventory → mail → guilds → housing → auctions → companions.
- Introduce feature flags to route specific subsystems to Rust; others still handled by .NET (via proxy) until parity.

Phase 4 — Cutover & Cleanup
- Switch game ports to Rust service; disable proxy paths.
- Archive MySQL; ensure all new writes hit PG; finalize backups and runbook.

Rollback Points
- After each phase gate, keep the prior system hot/warm to revert DNS/compose routing within minutes.

**Data Migration Playbook (MySQL→PostgreSQL)**
- DDL translation: generate PG DDL from `SQL/aaemu_*.sql` replacing types and identities; keep FKs aligned.
- Data load ordering: load reference tables → parent tables → child tables; defer FKs if needed.
- Tooling options: `pgloader` for fast copy; or `tools/migrate` using `mysql`/`tokio-postgres` streams with batched COPY.
- Integrity checks: row counts per table; sum checks on key columns; random samples; domain‑specific invariants (e.g., inventory slot uniqueness, mailbox ownership).
- Timestamp normalization: convert to UTC; fill missing with sensible defaults; audit ranges.
- Downtime window: initial full sync offline; if necessary, add dual‑write in .NET for a short delta window, then apply incremental catch‑up.

**Protocol Compatibility Strategy**
- Create `aaemu-protocol` with exact field ordering/encodings; port cipher/compression if any.
- Golden tests: decode/encode round‑trip against captured frames from the .NET servers.
- Wire‑compat proxies for migration: optional TCP proxy that logs and asserts protocol invariants while swapping backends.

**Service Responsibilities in Rust**
- Login: account auth, session tokens, anti‑abuse throttles, server list; state in PG (`aaemu_login`).
- Game: world loop, sessions, movement, combat, chat, trading; dynamic state in PG (`aaemu_game`); design reads from SQLite.
- Shared domain: IDs, localization support for Korean/English mapping from `compact.sqlite3`.

**Observability & Ops**
- Structured logs with `tracing` (JSON); include session, account, character IDs.
- Metrics: connections, ticks, handler latencies, DB pool usage; export `/metrics` for Prometheus.
- Health endpoints: `/live`, `/ready` with DB checks.
- Runbook: backup PG (base + WAL), rotate; compact SQLite remains static.

**Docker & Config**
- Compose services: `postgres`, `login-rs`, `game-rs`.
- Volumes: PG data; bind‑mount `./.server_files/AAEmu.Game/Data/compact.sqlite3:/app/Data/compact.sqlite3:ro`.
- Env: `DATABASE_URL` for each service; secrets via `.env` in dev, swarm/Secrets in prod.
- Ports: map existing ports to Rust services to avoid client changes.

**Testing & CI**
- Unit: protocol encode/decode, domain logic, SQLite query helpers.
- Integration: `sqlx` migrations up, seed minimal fixtures, run DB‑backed tests; optional testcontainers.
- Conformance: replay captured sessions vs. Rust services; assert responses match .NET golden outcomes.
- CI: GitHub Actions matrix (lint, build, test); cache `sqlx-data.json` for offline checks.

**Risks & Mitigations**
- Data type drift (booleans/enums): thorough DDL review, invariants in migrations.
- Transaction semantics differences: revisit upserts (use `ON CONFLICT`), isolation expectations.
- Performance regressions: add early benchmarks; profile with `tokio-console`/`pprof`.
- Protocol edge cases: expand golden corpus; canary behind feature flags.

**Acceptance Criteria per Phase**
- Phase 1: PG schema passes migration and integrity checks; parity in row counts and sampled records.
- Phase 2: Rust Login passes auth flows with existing client; stability ≥ 7 days; SLOs documented.
- Phase 3: Rust Game handles core loops (login→spawn→move→chat) for ≥ X concurrents; subsystem parity checklist green.
- Phase 4: All traffic served by Rust; MySQL retired; runbook updated; incident drills passed.

2) PostgreSQL Foundations
- Author PG DDL

3) Data Migration CLI (MySQL → PostgreSQL)

9) Per‑Table Migration Tasks (aaemu_game)
- For each table, deliver: PG DDL, loader, repository API, invariants, and tests.
- abilities: PK (id, owner); owner FK→characters.id; invariants: exp ≥ 0.
- accounts: PK (account_id); timestamps → timestamptz; trigger → PG trigger for updated_at. Invariants: non‑negative balances; last_* monotonic.
- actabilities: PK (owner,id); invariants: point ≥ 0, step in range.
- appellations: PK (id,owner); boolean active.
- auction_house: identity PK; client_name/bidder_name collation → `citext` or lower‑cased index; time columns tz; scheduler on `end_time`.
- blocked: PK (owner,blocked_id); owner self‑block disallowed.
- characters: PK (id, account_id) → consider surrogate PK on id, unique(account_id,id) or unique name; blobs (`unit_model_params`, `slots`) → `bytea`; money → bigint; default zeroed timestamps → `timestamptz` nullable; indices on account_id, name.
- completed_quests: PK (id,owner); data blob → `bytea`.
- doodads: identity PK; many ownership FKs (owner_id, item_id, house_id, parent_doodad, item_container_id) with `on delete set null` where appropriate.
- expedition_members: PK (character_id); name `citext`; role policies enforced in app.
- expedition_role_policies: PK (expedition_id, role); booleans for flags.
- expeditions: PK (id); owner/name `citext`.
- family_members: composite PK; ensure consistent naming.
- friends: PK (owner,friend); symmetric insert enforced by app or trigger; dedupe.
- housings: PK (id); coords indices; ownership FKs.
- items: PK (id); FK owner/container; unique(container_id, slot); serialized `info` fields → mapped columns/bytea.
- mails: PK (id); sender/receiver FKs; attachments linkage; read/unread flag; expiry index.
- mates: PK (id); owner FK; stats columns, timestamps tz.
- options: PK (owner); JSONB for options map preferred.
- portal_book_coords: PK (id,owner); coords ints; zone indices.
- portal_visited_district: PK (id,subzone,owner).
- quests: PK (id,owner); status enum → smallint; data → bytea.
- skills: PK (id,owner); type enum → text/check.
- uccs: identity PK; data → bytea; color channels bounds check.
- music: identity PK; title `citext`.
- item_containers: PK (container_id); type → text; size bounds; owner/mate FKs.
- slaves: PK (id); owner/summoner FKs; coords floats.
- ics_skus: identity PK; FK to `ics_shop_items`; counters non‑negative.
- ics_shop_items: identity PK; optional name override `text`.
- ics_menu: identity PK; indices for tab/sub_tab.
- audit_ics_sales: identity PK; indices as in MySQL; tz timestamps.
- audit_char_sus: identity PK; columns mapped; free‑text category; indices on account/character.
